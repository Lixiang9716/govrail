# Agent Note: issue 批次 #401-#420 — 失败报告的保真度(头条/内核/分区/动词)

Status: implemented

## Problem

采用方在真实失败现场反复拿到"说谎或不完整"的报告(#404/#409/#413/#419/#420/#401/#408/#416):self-test 的失败头条引用的是恰好最后打印的 PASS 行(每次运行不同),真正的拒绝用例埋在输出中段;pre-push 摘要对输出 JSON 的门引用单个 `{` 字符,结论要重跑门再解析 600 行才知道;`task close` 的拒绝把 SKIP(从未被评判)与 FAIL(树要回答)并列成同一形态的一个名单;stale-pin 修复提示指向不存在的子命令 `re-pin`(实为 `repin`),照抄即错;`decision add` 成功消息教的是已弃用别名;verify-plane 无终端拒绝漏说 `--reason`,agent 照提示走完再被拒一轮;10s 用例预算装不下需要构建的证明,而唯一合法的 skip-on-absent 逃生口没有写在任何作者会读的地方。

## Decision

报告的每一层都改为从"实际失败的东西"取词:self-test 失败时向 stderr(门 runner 摘要引用的通道)打一行出自失败清单的头条, PASS 行永不成为头条;runner 的摘要引用经 `_diagnostic_line`——JSON 输出解析出内核(诊断字段优先,其次首个列表首元素),非 JSON 退回首个有内容的行;`SKIP` 的原因写进记录并以 `--- skipped, not evaluated ---` 块逐门列出,`task close` 的拒绝把 `failed:` 与 `skipped, not evaluated:` 分行、并声明 SKIP 不是绿证据;task stale-pin 提示与 close preflight 改用真实动词 `repin`;`decision add` 消息改指 `gov decision verify`;verify-plane 首次拒绝一次性说全 `--confirm-unattended` 与 `--reason`;失败摘要行在 ≥1s 时附墙钟时长(饿死类故障"此处 121s、独立 69s"自证);rejections README 增补 skip-on-absent 预算段与"加用例=plane change 需重封"段,`--explain` 补同款一行;self-test 识别用例首行输出的 SKIP 标记为独立报告行(退出语义不变)。

## Alternatives considered

头条修复曾考虑在 runner 侧猜测"哪行是真失败"(放弃:runner 无法知道 self-test 的语义,分层越界);JSON 内核曾考虑只取首行跳过花括号(不够:pretty-print 的空结构行后仍可能是上下文标量,故先诊断字段、再首个列表元素——finding 形载荷的首元素才是行动点);task close 的 SKIP 曾考虑改为不阻塞(拒绝:SKIP 意味着证据缺失,冒充绿即 #329 修过的砖死形态);时长字段曾考虑全量显示(亚秒门的 `ran 0.0s` 是噪音,≥1s 才有诊断意义);`timeoutRetries` 重试机制未做——命名超时+时长+独立重跑命令已覆盖其诉求,重试会掩盖调度致红的真相。
