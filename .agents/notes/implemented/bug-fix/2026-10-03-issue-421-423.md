# Agent Note: #421/#423 — 基线探针分类;回执与自己的证据解耦

Status: implemented

## Problem

两个 fresh-clone 事故类(#421/#423):① 门依赖未跟踪物化产物(同步出的 closure)的仓库里,新 checkout 的 self-test 连红三个"restore 腿"项目用例,失败读作用例或门的缺陷,真实原因(声明门在未动树上本来就红——物化步骤没跑)不在输出、分类行或 doctor 的任何地方,三个会话各自从零重推;② `git add -A` 习惯把 .gov/last-run 的证据文件收编为 tracked 后,每次 run 的证据轮写都在弄脏它正要认证的树:回执永远 dirty=true,`receipt verify` 一票否决,而 `task close` 的绿判定没有 dirty 项——同一回执,close 判绿、verify 拒绝,双消费者同 run 异裁且各自不说标准。

## Decision

self-test 在项目用例失败时,按用例声明的 `# gate: <id>` 对未动树做一次进程内基线探针(直接调 runner 的 run_gates,不走子进程——子进程会解析到路径上的旧副本并继承 seal 拒绝):门红 → 失败归类 environment-suspect,点名"先修基线(新 checkout 通常是物化步骤)";门绿 → 保持 unclassified 与手复现提示;探针不可跑不分类。回执侧(D69):tree_state 的脏判定排除 .gov/last-run/ 与 .gov/history/ 前缀(扩展 history 天然 untracked 豁免);run 写证据时治愈追踪——ls-files 命中即 git rm -r --cached + ensure-ignore + 点名通告;task close 成功输出声明自己的绿标准(全选门全评、无 fail 无 skip)并说明 receipt verify 用更严的净树标准可能仍拒。

## Alternatives considered

#421 曾考虑 doctor 加基线探针(doctor 跑全 DAG 改变其"快速环境检查"契约)与 worktree 快照跑用例(创作回路问题,D67 已否);探针曾用子进程 `gov run --gate`(被否:解析到安装副本、继承 seal 拒绝,两个来源都不属于分类语义)。#423 曾考虑只治愈不豁免(治愈前窗口回执仍自否,误 tracked 复发)与只豁免不治愈(status 永挂 runner 脏文件);close 侧曾考虑把绿判定加严对齐 verify(否:close 的证据成本是自己的 DAG run,#323 的簿记豁免是刻意设计——对齐的正确方向是各自把标准说出来,不是互相假装)。
