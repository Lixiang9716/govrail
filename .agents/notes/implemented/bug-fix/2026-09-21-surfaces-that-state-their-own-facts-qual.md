# Agent Note: surfaces that state their own facts: qualified run summary, documented suppression marker, discharged escalations, artifacts split from sources

Status: implemented

Related: D25, issues #333, #354, #355, #356, #357

## Problem

Five surfaces whose output was true and unreadable — each one a place
where a reader had to reconstruct context the tool already held.

- **`gov run`'s final line was unqualified (#355).** The same tree
  answers `8 gates: 8 pass` under `--base HEAD~1`, `9 gates: 9 pass`
  under another base and `12 gates: 12 pass` bare; the reasons live in
  per-gate lines the truncation eats first. Read as text it looks like a
  contradiction; the "12 vs 13 configured" question is the same silence
  that hid the #329/#339 receipt disagreement.
- **`gov check --help` promised "counted, never invisible" suppressions
  and never said how to write one (#333).** The first real C++ file
  judged by the gate hit unexpanded SDK macros (`EXTERN_C_START`) and
  the reader's only path was restructuring the code, because the marker
  syntax and its placement rules existed only in code.
- **`surprise record`/`list` named a gate adopters do not have (#354).**
  The record-time message said "the surprises gate stays red until …",
  pointing at `scripts/check_surprises.py` — govrail's own self-hosted
  wiring, absent from the wheel and from the shipped gates.json. Worse,
  `ESCALATION OWED` was a pure count: it rendered identically before and
  after the required note shipped, so the one distinction an operator
  acts on was the one the surface could not show.
- **The similarity hint answered with unrelated signatures (#356).** The
  have-I-seen-this-before lookup shared words like "the/gov/task/gate",
  so a genuinely new signature was shown three unrelated ones — teaching
  the reader to ignore the hint.
- **`note-presence` counted evidence as prose (#356).** A PR carrying a
  logcat dump, an `unzip -l` listing and screenshots was reported as
  "13 non-trivial file(s)", implying ~13 decisions where there were ~3.

## Decision

- The run summary carries a bracket naming the mechanism that selected
  the set (`[mode: all]`, `[path-scoped vs HEAD~1, 3 gate(s) out of
  scope]`, `[every enabled gate]`), and a mode-selected run names the
  enabled gates the mode omits — one line, only when something is
  actually omitted (`--json` keeps stdout pure, so it goes to stderr).
- `gov check --help` documents the suppression mechanism end to end: the
  `gov:ignore-check <rule-id>` marker, its two legal placements (the
  finding's line, or anywhere in the node's row span), the count in the
  summary and in the stats ledger, and the path-level
  `.gov/checks/exclude.json` alternative.
- The surprise strings describe the obligation (`ship a process note
  citing surprise:<sig>`) instead of a gate the adopter may not have,
  and `gov surprise list` reads `.agents/notes/**` and reports
  `ESCALATION DISCHARGED (note <path>)` — the same scan govrail's own
  surprises gate runs, now on the read side of the ledger.
- The similarity hint requires two shared content terms after a stopword
  filter (the words every entry here shares are exactly the ones that
  carry no identity); an empty answer is a fine answer.
- `note-presence` splits its count into source files and data/artifacts
  by extension, and when the change is artifacts only it says so and
  points at the manifest's `note_presence_exempt` instead of asking for
  a note about a screenshot.

## Alternatives considered

- **A `problem:`-prefixed protocol for gate output** (raised in #341) —
  not this batch, but the qualification work here is the same instinct:
  make the surface say which of its lines is the verdict. Left for a
  decision when a gate actually needs it.
- **Making `gov surprise list`'s discharge check a shipped gate** —
  rejected: blocking escalation is the adopting project's wiring choice
  (#314's resolution); the read side can be honest without imposing a
  verdict, and govrail's own plane keeps its gate.
- **Reporting only a count of near-matches for the surprise hint** —
  rejected: a count with no names is unactionable; two shared content
  terms is a cheap, explainable bar, and the sig itself remains the
  user's deliberate choice (rule 11's own text).
- **An option/marker inside the artifact** for #356 — rejected:
  artifacts are often generated by tools that will not carry a marker,
  and an extension split costs nothing to explain; the manifest
  exemption stays the loud, opt-in path.
- **Naming `--explain`'s surface on the run summary too** (e.g. printing
  mode in the header) — rejected for now: the bracket answers the
  question at the line the reader is already looking at, and a header
  line competes with gate output for the head of a truncated report.
