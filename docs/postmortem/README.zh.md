# 尸检报告

[English](README.md) | 中文

当一次失败同时满足"隐蔽、系统性、重新发现代价高"时才写尸检。有意思的部分是流程为什么放过了它,而不是一行修复。

## 结构

- **Executive summary** —— 忙碌的读者三十秒能吸收的一段:什么坏了、平实语言的根因、为什么逃逸、持久的教训。
- **Timeline** —— 可观察的时序,附读者可验证的证据位置(文件、日志、序号)。
- **Root cause** —— 机制陈述,让同类问题下次可被认出。
- **Guardrails added** —— 这次失败催生的门禁、测试或规则,逐条链接。

## 规则

与修复护栏在同一个 PR 里写,或在护栏落地后的第一个 PR 里补写——否则不写;没有链接护栏的尸检只是故事。结构由门强制(`postmortems` 门,`scripts/check_postmortems.py`):四节必须以同一种标题词汇齐备,护栏节里每个指针都必须可解析。永不点名个人;失败的是流程,不是某个人。
