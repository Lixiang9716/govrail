# Persistence

English | [中文](README.zh.md)

Every format the plane itself writes to disk — seals, ledgers, task
cards, receipts, manifests — is user data an adopter depends on across
versions. This directory is the acknowledgment chain that keeps those
shapes from changing silently: a shape may change, but only with a
record that says so, classifies the compatibility impact, and chains to
the record before it.

## The pieces

- `schemas/<type>.schema.json` — the CURRENT declared shape of each
  persisted format: artifact, writer, readers, runtime class
  (`tracked` / `runtime-deletable`), and fields. Authored from the code
  that writes and reads the format.
- `changes/NNNN-<topic>.md` (+ zh pair) — one acknowledgment per
  change, each carrying exactly one fenced JSON block: the record
  number, date, class (`baseline` / `compatible` / `breaking`), and the
  per-type `before`/`after` digests it touches. Unfinished drafts
  containing `TODO` fail verification.
- `catalog.json` — GENERATED by `scripts/check_persistence.py
  --update`; never hand-edited. Maps each type to its live schema
  digest and latest record.

## The rules

- The first record for a type is its `baseline` (`before: null`); every
  successor's `before` equals the predecessor's `after` per type it
  touches — a linear chain, no forks.
- The newest record's `after` for a type must equal the live schema
  file's digest: **touching a schema without a record is red**, and so
  is a record claiming digests the files don't have.
- Classes: `compatible` keeps older readers working; `breaking` means
  older readers must refuse loudly and `gov update` owns the migration,
  stated in the record.
- `runtime-deletable` formats (`.gov/history/`, N9) are acknowledged
  but never migrated — readers still fail loud on shapes they don't
  know.
- What verification honestly proves: in-tree consistency of the chain
  and its anchor to the declared shapes. That the CODE conforms to the
  schemas is review and tests, not this gate — the same limit DSH
  states for its own verifier.

The gate is `persistence` (blocking, dogfood-only). Write a record in
the same PR as the format change — a schema change without its record
never leaves the machine.
